## Supabase findings

- Table, column and RPC names match in all code that was read.
- `debts` has no `direction` column. `attendance_records` has no standard-hours snapshot.
- FKs from `goals` and `savings_transactions` to `savings_goals` are RESTRICT. `incomes.salary_payout_id` is SET NULL.
- DB TimeZone is UTC; frontend uses browser local date.
- Live data: expenses 0, incomes 0, attendance 0, payouts 0, repayments 0, savings transactions 0, debts 4 (consistent), goals 2. Triggers have not run on real data.
- 13 live migrations vs 1 in the repo.

## Security

- RLS enabled on all public tables, owner-scoped policies, `anon` has no grants.
- RPCs are SECURITY INVOKER with pinned `search_path`.
- No `service_role` key, no key injection in `vite.config.ts`, no `dangerouslySetInnerHTML` in `src`.
- Leaked-password protection is off (P-07).
- Client-side cooldowns are UX only.
- RLS enforcement at runtime: NOT VERIFIED.

## Verified good (static, not run live)

- Expense, income, debt and attendance writes await, use `.select()`, filter by `user_id`, and throw on error. Deletes check the returned row count.
- Salary formula matches the live trigger. Snapshots are preserved on edit (`repository.ts:2285-2314`).
- `current_balance` mapping (`repository.ts:735`).
- Settings reset uses `auth.uid()` server-side, passes no user id from the client, and is guarded by `requirePersistenceContext`. Not executed.
- Double-submit ref guards on Expenses, Income, Debt, Work, Salary forms, Settings, QuickAction, Goals/Savings. Archive and reset have in-flight maps.
- `index.css` forces 16 px inputs on touch devices.
